# 橋を渡れ！

崩れやすい吊り橋を、みんなで同時に渡る 3D パーティゲーム。急ぐと板が割れる。慎重すぎると時間切れ。
リンクを送るだけで、スマホのブラウザから参加できる。

- 人数: 1〜100人（1人でも試せる）
- 1回: 40〜90秒（人数で少し延びる。ロングは約3分）＋秒読み3秒
- 手元のポート: 8105

画面は 3D（Three.js r185、`public/vendor/`）。自分の少し後ろ・上から向こう岸を見る追いかけ視点。WebGL が使えない端末は、真上から見た 2D の描画に自動で戻る（`?2d` を付けると 2D で確かめられる）。

## 遊び方

1. ニックネームを入れて「部屋を作る」。出てきた招待URL（/r/コード）か4文字の参加コードを送る
2. ホストが橋（5つ）を左右の矢印で選んで「スタート」。選んだ橋は参加者の画面にも出る
3. 秒読みの間、カメラが橋全体を見下ろしてから自分の後ろへ下りてくる。「わたれ！」で全員が同時に渡り始める
4. 画面を**ドラッグ**すると歩く（指を置いた所がスティックの中心。上＝奥＝向こう岸）。「**走る**」は1回押すと入りっぱなし、もう1回で切れる
5. 「待って」「行け」「危ない」の合図で周りに声をかけられる（頭の上に吹き出し）
6. 時間内に**全員の7割**が向こう岸に着けば**チーム成功**。個人は着順（着けなかった人は進んだ距離）で順位がつく

PC: 矢印キー / WASD で移動、Shift か Space を押している間だけ走る、1・2・3 で合図。右上の虫めがねで引きの視点。

## 橋（コース）

どの橋も「区間」（支柱と支柱の間、7段）を手前から並べたもの。**後ろの区間ほど仕掛けを重ねる**ので、1回の中でだんだん難しくなる。さらに時間がたつほど突風の間隔と落石の間隔が短くなる。

| 橋 | 区間 | 中身 |
|---|---|---|
| 森の吊り橋（★1） | 4 | 傷んだ板 → 突風 → 最後に振り子の丸太 |
| 赤い谷の大橋（★2） | 6 | 突風、落石、途中に石のやぐら、丸太、最後は落石が2倍 |
| 氷の吊り橋（★2） | 5 | 凍った板（すべって止まれない）が奥ほど増える。丸太と突風 |
| 火山の橋（★3） | 6 | 焼けた板（近づくと燃え始め、勝手に燃え落ちる）、落石、突風、丸太 |
| 大冒険（ロング、★3） | 12 | 森→谷→氷→火山を一気に。やぐら3つ。景色（空・霧・谷底）が場所で切り替わる |

区間の定義は `public/courses.js`（サーバーと画面が同じものを読む）。

## ルール

| 要素 | 中身 |
|---|---|
| 橋の幅 | 人数で変わる（3人まで3列、100人で18列） |
| 板の耐久 | 1枚ずつ耐久がある。乗っているだけで少しずつ減る。最初から傷んでいる板（ひび）が区間ごとに5〜22% |
| 重さの上限（板） | 1枚に重さ2.5まで。歩く人は1、走る人は2。超えると急に傷む（3人で乗ると約3秒で割れる） |
| 重さの上限（区間） | 区間ごとに「列数×1.3」まで。超えると区間の全部の板が傷む（橋が揺れて「ゆれ」「重すぎ」の札） |
| 走る | 速さ1.8倍。ただし重さ2倍＋足元の板を揺らして傷める |
| 突風 | 区間に予告（黄色と黒のしま、1.5秒）→ 吹く（2秒、風の筋）。吹いている区間で動いている人は重さ3倍。止まっていれば普段どおり |
| 丸太 | 区間の真ん中の段を振り子の丸太が横に振れる。当たると振れる向きに飛ばされ、端なら谷へ |
| 落石 | 床に影と赤い輪で予告（1.3秒）→ 落ちる。下にいるとぺしゃんこで少し動けない。板も傷む |
| 凍った板 | すべって急に止まれない・曲がれない |
| 焼けた板 | 誰かが手前まで来ると燃え始め、約60秒で燃え落ちる |
| やぐら | 石の段。割れない。通ると、落ちたときにここから戻れる（緑の旗） |
| お守り | 傷んだ板の上に置かれがち。拾うと個人の得点 |
| 落ちる | 割れた板の上にいると落ちる。2.5秒後にスタート（やぐらを通っていればやぐら）へ戻る |
| 橋が落ちる | どこかの段が全部割れると橋が落ち、乗っていた人は全員落ちて終わり |
| 星 | 成功で1つ。落ちた回数が人数の半分以下で+1。チームの到着が基準秒以内で+1 |
| 称号（その回） | 一番乗り / 橋にやさしい / 破壊王 / 落下王 / お守り長者 / ふっとび王 / しんがり |
| 記録（端末ごと） | 橋ごとの自己ベストと星。渡りきった回数で肩書きが上がる（見習いの渡り人 → 渡り職人 → 吊り橋の達人 → 谷の名人 → 伝説の渡り人） |

色だけに頼らない: 傷んだ板はひびの数、重すぎる板は赤い点滅、区間は「ゆれ」「重すぎ」の札、突風はしま模様と文字の帯で出す。

## 3D の見た目（`public/view3d.js`）

- 橋の x → 3D の x、進む向き y → 3D の -z（1 = 板1枚 = 1m）。サーバーの判定はそのまま、立体で見せるだけ
- カメラ: 自分の後ろ・上（俯角約20度）から奥を見る。向きは固定なので「スティックの上＝画面の奥」「右＝右」がずっと一致する。狭い橋は真ん中寄り、広い橋は自分を追う。縦持ちは少し引いて画角を広げる。自分が落ちると谷底をのぞきこむ
- 橋: 板は InstancedMesh（1枚1つ）。区間ごとにたわみ、重いほど沈み、重すぎ・突風で横に揺れる。割れた板は2つに割れて落ちる。ひびは2段階の絵を重ねる
- 人: 頭の大きいちびキャラ。帽子3種と服の色。表情は 普通 / 気合い（走る）/ 不安（割れかけ・重すぎ・突風）/ 驚き（落下・橋が落ちた）/ 目が回る（ふっとび）/ 笑顔（ゴール）。頭はカメラのほうへ振り向くので、後ろ姿でも表情が見える
- 落ちると手足をばたつかせて谷底へ落ち、しぶき（雪は氷のかけら、火山は火の粉）。ゴールすると跳ねて両手を上げ、自分のときは紙吹雪
- 背景: 場所ごとに空のグラデーション・霧・谷の壁・木・谷底（川 / 氷 / 溶岩）。雪山は雪、火山は火の粉が舞う
- 重さ対策: 画素比の上限（画質 高2 / 中1.5 / 低1）、影は1灯で控えめ、板・手すり・岩・木・粒は InstancedMesh。fps が 42 を切ると画質を1段下げる（スマホは中から）。近い人だけちびキャラ（スマホ14人 / PC22人）、ほかは簡単な形をまとめて描く。カメラの目の前の人は消す
- 名前の札・合図の吹き出し・「ゆれ」の札は HTML を 3D の頭の上に重ねる

起動の見張り: index.html の素の script がエラーを集め、エラーがあれば8秒、無くても20秒で起動しなければ原因を画面に出す。後から起動できたら app.js が消す（遅い回線での誤表示を防ぐ）。

## 大人数対応（負荷試験）

### やったこと

雛形の送り方は「毎 tick（20回/秒）、人ごとに全状態を作って JSON にして送る」。100人だと 1 tick で 100回の view と JSON 化が走り、
1回の中身も100人分あるので、送る量は人数の2乗で増える。これを次のように変えた。

1. **ゲーム中は差分だけを送る**（`t:'f'`）。動いた人と、耐久の段階が変わった板だけ。2秒に1回だけ全員分をまとめて送る（取りこぼしの保険）
2. **全員に同じ中身は1回だけ JSON にして使い回す**。このゲームには秘密が無いので、差分は Buffer を1つ作って全員に送る。部屋の全体の状態（ロビーや結果）も、共通部分を1回だけ JSON にして人ごとには `you` だけ足す（`meta.sharedView`）
3. **位置は 0.1 単位の整数**、状態は番号、板の耐久は 0〜10 の段階にして短いキーで送る（`p:[番号,x,y,状態,...]`）
4. **物理は20回/秒、配るのは10回/秒**。画面側は2つの差分の間を補間し、自分だけは押した瞬間に動いて見せる（サーバーの位置へ少しずつ寄せる）
5. 画面側の入力は「変わったときだけ・最大15回/秒」

比較のため、雛形と同じ送り方も `BRIDGE_NAIVE=1`（`node tools/load.mjs --naive`）で残してある。

### 測り方

- `tools/load.mjs` がサーバーを別プロセス（`STATS=1` で `/stats` を開く）で起動し、ws クライアントを N 本つないで1部屋で遊ばせる
- ボットは 150ms ごとにランダムな向き（前寄り）へ動き、3割は走る（1人あたり約6.7回/秒の操作。人の操作より多め）。2%の確率で合図も送る
- 各20秒。ゲームが終わったら即再戦して、測る間はずっとゲーム中にする（「再戦」列が回数）
- サーバー: 送信量（ws に渡したバイト数）、tick の所要時間（ゲームを進める＋送るまで）、CPU（process.cpuUsage）、メモリ（RSS の最大）
- クライアント: 1秒ごとの ping の往復時間、1人あたりの受信量、差分が届く間隔
- 環境: この Mac（Apple M5、10コア、16GB、Node v26.4.0、**電池駆動**）の localhost。サーバーとボットは別プロセスだが同じマシン（2026-10-26 測定）

### まだ残っているボトルネック（数字）

- **送信量は今も人数の2乗で増える**: 1回の差分は「動いている人数」に比例し（100人が全員動くと約 0.9 KB）、それを全員に送るため。10→30→50→100人で 15→92→239→888 KB/s。
  100人で約 7 Mbps。1部屋100人なら問題ない量だが、100人部屋を同時にいくつも開くと、CPU より先に回線の上限が来る
- 次に効く手（未実施）: 差分をバイナリ（1人5バイト程度）にする → 約半分 / 自分から遠い人は5回/秒に落とす / 画面に入っていない人を送らない（ただし右端の全体図で全員を出しているので、仕様と相談）

### この数字の限界

- localhost なので回線の遅延・帯域・パケットロスは入っていない。ping 往復 1〜2ms は「サーバーの処理待ちが小さい」ことを示すだけで、実際のスマホ回線の遅れ（数十〜数百ms）は別に乗る
- 本番サーバー（Render の無料プラン等）はこの Mac より CPU が遅く、帯域や同時接続にも上限がある。同じ数字にはならない（未確認）
- ボットは画面を描かない。**100人を描くスマホ側の重さ（fps）は実機で測っていない**（headless の chromium / webkit で表示と操作が通ることだけ確認）
- 実際の人間10人での同時プレイはしていない。10人は ws ボット（load.mjs）と、ブラウザ1台＋ボット9人（layout.mjs）、ブラウザ3台（e2e.mjs）で確かめた

## デプロイ

1フォルダ＝1サービス。どれも契約が要るので、まだ公開していない。

- Render: render.yaml をそのまま Blueprint に使う（`healthCheckPath: /healthz`）
- Fly.io / Cloud Run 等: Dockerfile（node:22-alpine、PORT=8080）
- og:image は index.html を返すときに、来たホスト名（`x-forwarded-host` / `host`）で絶対URLに書き換える。プロキシが `x-forwarded-proto: https` を付ける前提（各サービスで付くかは未確認。付かないと http の URL になる）
- `/stats` は環境変数 `STATS=1` のときだけ開く（本番では付けない）

## 今後の改善点

- 差分のバイナリ化と、遠い人の更新を間引く（上の「まだ残っているボトルネック」）
- 突風の頻度・板の耐久・時間は、実際に遊んだ感触で調整が要る（ボットのシミュレーションでは「全員で一斉に走ると100人なら10秒前後で橋が落ちる」「時間差で出ると成功する」まで確認）
